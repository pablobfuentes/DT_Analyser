# Report Filter Engine

## Two filter layers

### Global filters

Reused from Dashboard (`DashboardFilters`):

- `start_date`, `end_date`
- `account_id`
- `source_type`
- `direction`
- `ticker`

Applied at SQL query time via `build_closed_trades_query`.

### Exploration filters

Generated by clicking report buckets. Stored in `TradeFilterSet.exploration`.

## Click-to-filter behavior

- **Single-select per dimension** — clicking Thursday replaces Wednesday
- **Toggle** — clicking the active bucket again removes that filter
- **Combined** — exploration filters AND global filters apply together
- **Reset Exploration** — clears only exploration; global filters unchanged

## URL synchronization

Both layers serialize to query params on `/graphs`:

```
/graphs?range=all&weekday=WED&entry_15m=10:15-10:30&entry_price_bucket=5_10
```

Frontend: `utils/graphFilters.ts`  
Backend: `filters_from_query()` in `services/reports/filters.py`

## Drilldown to Trades

"View Matching Trades" links to `/trades` with compatible params (ticker, direction, entry time windows where mapped).

## Implementation

```python
@dataclass
class TradeFilterSet:
    global_filters: DashboardFilters
    exploration: dict[str, str]
```

`apply_exploration(features, filt)` returns True if trade matches all active exploration filters.

No raw SQL fragments from frontend — only validated param keys and bucket keys. Unknown query keys are ignored. `include_partial_feed` is a quality control (not an exploration dimension) and does not remove trades from Time/Behavior/Outcome reports.

Reset Exploration clears `exploration` only.
