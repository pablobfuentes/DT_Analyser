# Step 5 Plan — Pine Signal + Strategy Enrichment

**Status:** Implemented and audited 2026-09-02. See `docs/STEP_5_7_AUDIT.md`.

**Signal ID rule (permanent, matches SIGNALLOG):** `<STRATEGY_KEY>|<TICKER>|<TIMEFRAME>|<OPPORTUNITY_BIRTH_BAR_MS>` where birth bar is the ARMED bar millisecond timestamp (ENTRY bar if a strategy has no ARMED). Generated by Pine at ARMED and reused for ARMED / ENTRY / EXIT. The earlier `ENTRY_BAR_UNIX_MS` wording was contradictory and is superseded.

**Goal:** Preserve Pine Copilot strategy snapshots as first-class **Signal** entities, link them auditable to **Trades**, and activate the Step 3 **STRATEGY** Graphs section. No redesign of the report/filter/card architecture. No Step 6 manual-vs-AUTO comparison yet.

## C. Signal ID Design

### Format (canonical)

```
<STRATEGY_KEY>|<TICKER>|<TIMEFRAME>|<OPPORTUNITY_BIRTH_BAR_MS>
```

**Example:**

```
FIRST_PULLBACK|NCRA|1|1725280860000
```

`OPPORTUNITY_BIRTH_BAR_MS` is the **ARMED bar** `time` (milliseconds). It is known when ARMED fires; the future ENTRY bar is not required. Strategies without an ARMED lifecycle use the ENTRY bar timestamp.

### Rules

| Rule | Detail |
|------|--------|
| Generated by Pine | Analyzer stores verbatim; never re-derives |
| Deterministic | Same opportunity → same ID across re-import |
| Stable bar time | Use the ARMED (birth) bar open time in ms, not `timenow` |
| Lifecycle carry | ARMED → ENTRY → EXIT share one ID created at ARMED (or ENTRY if no ARMED) |
| Uniqueness | One strategy opportunity per ID; multiple same-day setups differ by birth bar |
| Legacy | Records without Signal ID get synthetic legacy ID + `legacy=true` |

### Pine generation (contract)

```pine
// At ARMED (or first ENTRY if strategy has no ARMED):
armedBarMs = time  // current bar time, milliseconds
signalId = strategyKey + "|" + syminfo.ticker + "|" + timeframe.period + "|" + str.tostring(armedBarMs)
```

Document fully in `docs/PINE_SIGNAL_SCHEMA.md` and `pine/PINE_SIGNAL_EVENT_SCHEMA.md`.

## D. Pine Export / Log Format

### Primary format: `PINE_SIGNAL_EVENT` (schema 1.0)

Tab-separated, one record per line, suitable for Pine Logs copy/paste.

**Header row (optional in file; required in schema doc):**

```
RECORD_TYPE	SCHEMA_VERSION	SIGNAL_ID	STRATEGY_KEY	STRATEGY_VERSION	TICKER	DIRECTION	TIMEFRAME	ORIGIN	EVENT_TYPE	EVENT_TIME	EVENT_PRICE	...
```

**Example ENTRY line:**

```
PINE_SIGNAL_EVENT	1.0	FIRST_PULLBACK|NCRA|1|1788360197000	FIRST_PULLBACK	Momentum Pullback Copilot v0.3.3	NCRA	LONG	1	REALTIME	ENTRY	2026-09-02T09:43:17-04:00	4.82	4.70	5.06	238	A+	12.5	8.4	7.2	28.6	BULLISH	true	true	true	RTH	...
```

### Parsing strategy

1. Detect `RECORD_TYPE` per line (first field or line prefix).
2. Validate `SCHEMA_VERSION` — supported: `1.0`; unknown → structured error, skip line.
3. Map columns by **name** when header present; positional fallback only for schema 1.0 with documented order.
4. Preserve `raw_line` and full parsed dict in `raw_payload_json`.

### Import sources

| Source | Enum | UX |
|--------|------|-----|
| Paste | `PASTE` | Text area on Import page |
| File upload | `TEXT_FILE` | `.txt`, `.tsv`, `.csv` |
| Pine log export | `PINE_LOG` | Same parser |

## E. Current TRADE_RECORD Compatibility

No samples exist in the repository today. Plan assumes legacy formats may appear in user logs.

### Expected legacy types

| Record type | Source | Plan |
|-------------|--------|------|
| `TRADE_RECORD` | Manual Copilot | Parse into synthetic signal + events; `legacy=true` |
| `AUTO_TRADE_RECORD` | Strategy Tester AUTO | Parse; may carry signal reference for explicit match |
| Unknown prefix | Any | Store in import errors; batch continues (PARTIAL) |

### Legacy TRADE_RECORD handling

1. Attempt field extraction (ticker, direction, entry time, gap, rvol, quality, etc.).
2. Generate **synthetic signal_id**:

   ```
   LEGACY|<strategy_guess>|<ticker>|<entry_unix_ms>
   ```

3. Mark `legacy=true`, `signal_origin=UNKNOWN` unless origin field present.
4. Conservative trade matching only; never claim EXPLICIT_ID confidence.

### AUTO_TRADE_RECORD

1. Parse like TRADE_RECORD with AUTO-specific fields.
2. If embedded Signal ID present → use for EXPLICIT match to AUTO trade.
3. Preserve compatibility with existing historical AUTO exports without requiring re-export.

## H. Trade-to-Signal Matching

### `trade_signal_links` table

| Column | Type | Notes |
|--------|------|-------|
| `id` | int PK | |
| `trade_id` | FK → trades.id | |
| `signal_id` | FK → signals.id | Internal FK |
| `match_type` | string | See below |
| `confidence` | Numeric(5,4) | 0–1 rule score, not statistical probability |
| `time_delta_seconds` | int nullable | entry trade − signal entry |
| `link_status` | string | `CONFIRMED`, `SUGGESTED`, `REJECTED` |
| `created_at`, `updated_at` | datetime tz | |

**Unique constraint:** `(trade_id, signal_id)` — one link row per pair; status updated in place.

### Match types and confidence

| match_type | When | confidence | Auto-confirm? |
|------------|------|------------|---------------|
| `EXPLICIT_ID` | Trade/source carries same Signal ID | 1.00 | Yes → CONFIRMED |
| `AUTO_EXACT` | AUTO trade; ticker+direction; entry within tight window | 0.98 | Yes if single candidate |
| `AUTO_TIME_MATCH` | AUTO; within tolerance | 0.90 | Yes if single candidate |
| `MANUAL_TIME_MATCH` | Manual; single candidate in window | 0.75 | **No** → SUGGESTED |
| `MANUAL_REVIEW` | User confirmed via UI | 1.00 | User action |
| `LEGACY` | Legacy record heuristic | ≤0.70 | SUGGESTED only |

### Configurable tolerances (`app/config.py`)

| Setting | Default | Purpose |
|---------|---------|---------|
| `LTA_SIGNAL_AUTO_MATCH_SECONDS` | 90 | AUTO entry vs signal entry |
| `LTA_SIGNAL_MANUAL_MATCH_BEFORE_SECONDS` | 30 | Manual early tolerance |
| `LTA_SIGNAL_MANUAL_MATCH_AFTER_SECONDS` | 180 | Manual late tolerance |
| `LTA_SIGNAL_PREFER_REALTIME` | true | Prefer REALTIME over HISTORICAL_REPLAY |

### Matching rules

**AUTO:**

- Same ticker, same direction
- `entry_signal_time_utc` within ±`AUTO_MATCH_SECONDS`
- Prefer REALTIME signals
- Exactly one candidate → auto-link CONFIRMED
- Multiple candidates → no link; flag AMBIGUOUS on signal

**MANUAL:**

- Same ticker, same direction, same NY trading day
- Window: `[entry_signal − before, entry_signal + after]`
- Prefer REALTIME
- Exactly one candidate → SUGGESTED (not CONFIRMED unless EXPLICIT_ID)
- Zero or multiple → no auto-link

**Never:**

- Match wrong ticker or direction
- Force pick when ambiguous
- Auto-link two MANUAL trades to one signal without review

### Multiple trades per signal

Allowed: one MANUAL + one AUTO may both link to same signal (Step 6 foundation).

Not allowed without review: two MANUAL trades → same signal.
